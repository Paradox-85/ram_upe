# Views — Human Surface Contract

Views are the **human interface onto canonical knowledge**. They exist because the canonical KB
is deliberately atomic: 520 capability records are excellent for search, traceability and agent
reasoning, and unreadable as a document set.

```text
Machine surface                        Human surface
knowledge-base/<collection>/<id>.md    knowledge-base/views/<name>.md
atomic, metadata-rich, authoritative   grouped, readable, NON-authoritative
                    ▲                                  │
                    └──────── references ──────────────┘   (never copies of record)
```

## Rules

1. **A view is never a second source of truth.** Nothing may be maintained only in a view.
2. **Generated views are marked as such**, with the generation command and date:

   ```markdown
   > **Generated / non-authoritative projection of canonical KB entities.**
   > Regenerate: `python tools/kb-views/generate.py`
   ```

3. **Prefer generating from metadata** over hand-maintaining. A hand-curated view must say so
   explicitly and must not contain facts absent from the KB.
4. **Link, do not duplicate.** A view may quote a canonical statement, but the record remains
   authoritative; if the view drifts, the KB wins.
5. **Only views with real use.** Do not create a view "because it might be handy".

## Initial views

| View | Purpose |
|---|---|
| `architecture-overview.md` | current architecture records, decision catalog, candidate domains |
| `capability-map.md` | the 520 atomic capability records grouped by candidate functional domain |
| `requirements-coverage.md` | Requirement → Capability → Evidence traceability |
| `gba-overview.md` | per-GBA navigation: received sources, non-canonical analysis, citing requirements |
| `vendor-overview.md` | vendor material held as evidence, plus KB records that mention each vendor |
| `architecture-committee.md` | committee hub: backlog, open decisions, ADRs, roadmap, review queue, reports |
| `roadmap.md` | projection of candidate priorities and requirement kinds (no governed roadmap exists yet) |
| `open-decisions.md` | decisions and questions needing human input |
| `reports.md` | audience deliverables by status, with links outside the KB |
| `sources-and-evidence.md` | where original material lives, how it is registered, evidence vs knowledge |

**Curated pages are not views.** `index.md`, `product-overview.md` and `contributing.md` live at the
KB root and are hand-written entry pages (they must still satisfy rule 1). Everything in this folder is
generated by `tools/kb-views/generate.py` and must never be edited by hand.

**Wiki note.** This folder is published as part of the Azure DevOps code wiki. Links to content outside
`knowledge-base/` are absolute repository URLs (see `tools/wiki/README.md`); in-KB links stay relative.
Do not hand-fix a "broken-looking" absolute URL — regenerate, or fix the record it comes from.

Regenerate with `python tools/kb-views/generate.py`.
